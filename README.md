This is the **frontend** of FinFlow (Next.js 15 App Router). AI, email, push
delivery, and jobs run on a separate backend: [`finflow-api`](https://github.com/Sadab-Munshi/finflow-api).

## Quickstart

```bash
npm install
cp .env.example .env.local   # fill values (names + purpose: docs/CONFIG.md)
npm run dev                  # → http://localhost:3000
```

The app needs the backend for AI/auth-adjacent endpoints — run finflow-api
locally (`NEXT_PUBLIC_API_URL=http://localhost:3001`) or point at the deployed API.

Production: `npm run build && npm start`. Deploy is Vercel (see `docs/DEPLOYMENT.md`).

> There are no automated tests; `npm run lint` and `npx tsc --noEmit` are the
> gates — builds ignore both (`next.config.ts:4-9`).

## Key features

- 4-mode transaction entry: **NLP text, voice, receipt scan, manual** (`/add`)
- Dashboard, budgets with 80/90/100% alerts, history with search/filter/PDF export
- AI insights + analytics suite (rolling averages, forecast, anomalies, YoY);
  AI usage governed by per-user daily/monthly + platform-wide admin limits
- Monthly PDF reports (generated by finflow-api), notifications, push
- Auth: email + Cloudflare Turnstile, Google/Microsoft OAuth, ban enforcement;
  reason-aware signup gating (open / invite-only / closed / domain allowlist)
- Platform control surfaces from Vertex: **maintenance lockout screen**,
  read-only + announcement banners, per-user evaluated **feature flags**
- en/hi/bn i18n · installable PWA with offline shell + push
- PostHog product analytics incl. instrumented events
  (`signup_completed`, `login`, `transaction_added`, `ai_used`) that power the
  admin funnels/cohorts ([docs/PLATFORM_CONTROLS.md](docs/PLATFORM_CONTROLS.md))
